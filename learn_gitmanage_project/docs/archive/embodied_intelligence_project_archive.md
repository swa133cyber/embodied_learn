## 1. 项目长期目标

围绕**机械臂操作**建立跨学科、可实践的具身智能学习路线。

目标是在约 3--4 个月内建立机器人学、控制、机器学习、强化学习、ROS 2
和仿真的入门基础，成长为能够独立完成基础机器人仿真项目的新手机器人工程师；之后继续完善项目，使其具备科学研究价值和进一步产品化的潜力。

时间安排可以延长，不以赶进度为目标。仿真项目不能直接等同于可投产产品，真实部署仍需硬件验证、安全性、可靠性和工程测试。

1.  以中文教学，表达清楚、直接，初学者友好，但不重复已经掌握的知识。
2.  用户重视效率：简单、可直接推导的原理，直接解释推导、例子和工程意义，不要求为了形式而运行实验。

4.  不因追求效率而省略主路线规定的关键实验和验收；只省去重复证明显而易见结论的无效实验。
5.  一次安排合理的下一步；用户要求完整学习单元时，再连贯给出该单元所需内容。
6.  代码提供必要注释；命令需要说明用途，不只给出命令。
7.  不反复使用用户以前的 STM32/PID 项目作类比，除非用户主动要求。
8.  每个学习单元结束时，更新进度、实验记录和下一步安排。
9.  不擅自认定用户已经保存文件、执行命令或完成配置；不确定时明确标注待核实。

### Day 4：开环与闭环控制

实验主体已完成，仍需确认是否已将记录保存到项目文件并完成路线验收。

原路线要求： - 记录一次成功过程的动作序列。 - 从相同起点回放。 -
改变起点或目标后回放原序列。 - 与重新读取状态的反馈策略比较。 -
解释何时回放成功、何时出现误差。 - 保存成功和失败案例，解释条件差异。 -
不从一次回放成功推导出机器人不需要反馈。

已有实验结果：

  实验   条件                     结果
  ------ ------------------------ -------------------------------
  A      原始闭环，从 0 到 5      最终位置 4.982，记录动作数 38
  B      相同起点开环回放         最终位置 4.982
  C      起点改为 1，回放原动作   最终位置 5.982
  D      起点改为 1，重新闭环     最终位置 4.982，33 步

已掌握： - 开环不根据执行过程中的状态变化主动修正。 -
闭环持续读取状态并重新计算控制动作。 -
初始状态变化会影响固定动作序列的结果。 -
中途受到外部扰动时，开环通常保留扰动造成的误差；闭环在反馈和控制能力足够时可以修正误差。 -
`dt` 是人为设定的时间步长/控制周期，不是由控制公式自动算出的。`dt=0.05s`
对应 20 Hz；当 `action` 表示速度时，`position += action * dt`
表示按时间步长更新位置。

### Day 4：机器人学辅助概念

已学习： - Link：连杆，近似视为刚性的结构。 -
Joint：关节，连接连杆并允许相对运动。 -
DOF：自由度，独立运动变量的维数。 - Revolute：旋转关节。 -
Prismatic：移动关节。 -
二连杆机械臂关节变量示例：`q = [theta1, theta2]^T`。 -
正运动学：由关节变量计算末端位姿。 - 逆运动学：由末端目标求关节变量。

## 10. 版本管理建议

每次完成一个学习单元并更新档案后，在确认 Git
仓库根目录正确的前提下执行：

``` powershell
git status
git add docs/archive notes
git commit -m "docs: update embodied learning progress archive"
```

如果代码也有变更，应按实际情况一并提交。提交前检查
`git status`，不要把大型临时输出、缓存目录或敏感信息加入版本控制。

建议至少保留两份副本： - 工作副本：项目目录内，由 Git 管理。 -
独立备份：项目目录之外的另一块磁盘、移动硬盘或可靠云盘。

仅把档案放在 GitHub 远程仓库不等于完整备份；最好同时保留独立副本。
